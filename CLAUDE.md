# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Personalized English learning tracker for one household with two profiles: a software
engineer and a nurse. Starts at A1, targets IELTS/OET B2-C1 for working abroad. Progress
is tracked per CEFR level and per skill (listening, reading, writing, speaking).

## Stack

Bun workspaces monorepo. Go 1.24+ + Postgres (`pgx`, `sqlc`, `goose`) in `apps/api` ·
`River` jobs · Anthropic SDK + Whisper · TypeScript PWA in `apps/web` (Next.js static
export, next-intl `id`/`en`, Tailwind 4, Serwist) · OpenAPI contract in
`packages/api-contract` → generated TS client in `packages/api-client` · Nix flake ·
single Docker image.

## Layout

- `apps/api/` — Go module `github.com/arifinoid/eng-geek/apps/api`; `cmd/`, `db/`, `internal/`, `content/`.
- `apps/web/` — Next.js app (`app/[locale]`, `i18n/`, `messages/`).
- `packages/` — `api-contract`, `api-client`, `tsconfig`.

## Gate

Run from the repository root; all must pass before a change is done:

```bash
gofmt -l apps/api     # must print nothing
go -C apps/api vet ./...
go -C apps/api test ./...
bun run lint:web
bun run typecheck:web
bun run test:web
bun run build:web     # static export must succeed
bun run typecheck:api-client
```

Toolchain via `nix develop` (go, bun, sqlc, goose, postgres). Database tooling (install
with Nix or `go install`; not vendored):

```bash
cd apps/api && sqlc generate
goose -dir apps/api/db/migrations postgres "$DATABASE_URL" up
bun run seed:api        # load content YAML + demo household/profiles
```

Integration tests need a migrated + seeded database and are excluded from the
default gate:

```bash
TEST_DATABASE_URL="$DATABASE_URL" go -C apps/api test -tags integration ./...
```

`apps/api/internal/store` is generated by sqlc from `apps/api/db/`; never edit it.

## Non-negotiables

- `skill` lives on `activities`, not `units`.
- Recording an attempt is one transaction; lock the `skill_ratings` row `FOR UPDATE`.
- An activity is done at `score >= 0.7`.
- Vocab SRS reviews never change skill ratings.
- A1 -> A2 gate: >=80% activities, checkpoint `overall >= 0.70`, all ratings `>= 1000`.
- `apps/api/db/migrations` is the schema source of truth; `internal/store` is generated.

## Conventions

- Code MUST be English: identifiers, comments, API/CLI messages, UI copy, test titles.
  Prose docs may be Indonesian.
- Do not commit secrets, `.env`, or personal data.
- Workflow: work on a branch, push, and open a PR. Do not merge; the user merges.
- Commit only when the user asks.
